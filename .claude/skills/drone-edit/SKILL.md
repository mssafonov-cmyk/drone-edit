# Монтаж дрон-видео (DJI) — операционный плейбук

Это доведённый до практики пайплайн: партия исходников → EDL/OTIO для Resolve +
превью цветокора + честный разбор + shot list. Финальный рендер пользователь
делает сам в Resolve. Правила проекта — в `CLAUDE.md`, параметры — в `config.yaml`.

Читай этот файл целиком, затем — нужный `references/*.md` под текущую задачу.
Доктрина отбора и ритма важнее скриптов: скрипты стабильны, а качество даёт
именно следование правилам ниже.

## Окружение (пути не в системном PATH — брать из `config.yaml → tools`)
- Python: `C:\Users\User\AppData\Local\Programs\Python\Python312\python.exe`
- ffmpeg / ffprobe: каталог WinGet Gyan.FFmpeg (полный путь в `config.yaml`).
- Консоль Windows — cp1251. В скриптах уже `sys.stdout.reconfigure(encoding="utf-8")`;
  свои временные скрипты — так же, иначе падают на кириллице.
- OpenCV на Windows НЕ читает кириллические пути через `imread` — только
  `cv2.imdecode(np.fromfile(path, np.uint8), ...)`.
- Модель для этой работы — **Opus** (смесь точного кода и творческих суждений;
  Sonnet пропускает тонкости отбора).

## Жёсткие правила (не нарушать — полностью в `CLAUDE.md`)
1. `input/`, `references/`, `color_targets/`, `music/` — ТОЛЬКО ЧТЕНИЕ. Всё
   промежуточное — в `work/`, результат — в `output/`.
2. **Финальный рендер — только после явного выбора варианта цветокора.** Этап 5
   выдаёт превью-варианты, не финал.
3. **Без комплиментов. Честный разбор** с таймкодами брака на каждом прогоне.
4. Фото-стиль ≠ дрон-лук. Пайплайн цвета ведёт `color_targets/target_drone/`
   (orange-teal), а не фото точки А. Подробно — `references/color.md`.
5. Общение по-русски, объяснять что и почему.

## 🔴 Протокол изоляции партий — САМАЯ ЧАСТАЯ ОШИБКА, читать первым
Пайплайн держит состояние в ОБЩИХ файлах (`work/clip_catalog.json`,
`work/clip_index.json`, список `REELS` в `scripts/stage4_reels.py`). Новая партия
молча затирает данные предыдущей. Реально сжигали 7 минут на пересчёт stage2.

Порядок для КАЖДОЙ партии:
1. `config.yaml → project.name` и `project.footage_dir` — переключить на партию.
2. Прогнать stage1 + stage2 (см. ниже).
3. **Сразу** забэкапить каталог под именем партии:
   `Copy-Item work/clip_catalog.json work/clip_catalog_<batch>.json -Force`
   (и `clip_index.json → clip_index_<batch>.json`).
4. Перед stage3/4 вернуть НУЖНЫЙ каталог в активный слот:
   `Copy-Item work/clip_catalog_<batch>.json work/clip_catalog.json -Force`
   (скрипты читают жёсткий путь `work/clip_catalog.json`).
5. Спеки монтажа в `REELS` именовать с суффиксом партии (`..._hongkong`,
   `..._turkey`) — список общий, легко взять чужие индексы/спецсимволы.
6. Финалы складывать в `output/<Batch>/`; `output/reels/` — рабочая свалка превью.

Реестр известных партий и их спек — `references/batches.md`.

## Карта пайплайна и команды
Запуск: `& <python> scripts\<stage>.py <args>` (python из config).

| Этап | Скрипт | Вход → Выход |
|------|--------|--------------|
| 0 калибровка стиля | `stage0_analyze.py` | references/ + color_targets/ → `work/style_profile.json` (разово) |
| 1 индекс | `stage1_index.py` | footage_dir → `work/clip_index.json` |
| 2 анализ+брак | `stage2_analyze.py` | → `work/clip_catalog.json` (посекундные метрики, сегменты hero/filler, plan_cuts). Ночной режим — авто по медиане яркости <55 |
| 3 музыка | `stage3_music.py <track.mp3>` | music/ → `work/music_grid.json` (онсеты, strong_beats, phrases, first_sound, energy_peaks) |
| 4 сборка | `stage4_reels_music.py [флаги] <spec> "<track>" ["<track2>"]` | → `output/reels/<spec>.{otio,fcpxml,edl,_preview.mp4}` |
| 5 цветокор | `stage5_grade_match.py` (двухэтапный) / `stage5_colorgrade.py` (3 варианта A/B/C) | превью рилса → варианты грейда |

Вспомогательные: `vertical_crop.py` (трекинг-кроп 16:9→9:16), `burn_captions.py`
(заголовок локации в кадр + сайдкар `_caption.txt` под все площадки),
`rerender_from_otio.py`, `otio_export.py`, `make_review_clips.py`.

**Спеки монтажа** (`candidate_idx`, `aspect`, `clip_len`, `target_len`) заданы в
`scripts/stage4_reels.py → REELS`; `stage4_reels_music.py` берёт спеку по имени.
Поле `"aspect": "16:9"` → горизонтальный рендер 1920×1080 без кропа; по умолчанию
9:16. **`stage4_reels.py` (не-music) устарел — не запускать, схема каталога другая.**

**Флаги `stage4_reels_music.py`** (ручная курация — обязательна, см.
`references/selection-rules.md`):
`--exclude`, `--prefer` (порядок!), `--end-with`, `--open-with`, `--window "idx.seg:start"`,
`--extend "idx.seg:sec"`, `--speedup-keys` + `--speedup-factor`, `--music-start N`,
`--max-sec N`, `--end-fade 2.5` (фильмы). Ключ — `"idx.seg"` (напр. `"27.0"`),
можно `"idx"` = весь клип. `--zoom-keys` РЕАЛИЗОВАН, но даёт дрожание — НЕ
использовать, заменять на `--speedup-keys`.

## Порядок работы над партией (типовой прогон)
1. **Изоляция + индекс.** Протокол выше → stage1 → stage2 → бэкап каталога.
   Проверить первые клипы: если ночная/тёмная партия дала 0 сегментов —
   сработал ночной режим, глянуть медиану яркости.
2. **Инвентарь.** По `clip_catalog.json` разложить материал по локациям/главам,
   посчитать чистые сегменты. **Если чистого материала мало — честно сказать и
   предложить короче, НЕ добивать браком** (главное правило пользователя).
3. **Музыка.** stage3 по трекам из `music/` (свои не качаю). Выбор трека — по
   `energy_peaks`/структуре под настроение; электроника режется в бит намертво,
   оркестр «плывёт». Вести `music/LIBRARY.md` (занято/свободно). Детали ритма —
   `references/rhythm-and-render.md`.
4. **Отбор + сборка.** Прогнать кандидатов через валидатор метрик ДО рендера,
   собрать `--prefer` только из чистых, выстроить драматургию вручную
   (`--open-with`/`--end-with`). Правила — `references/selection-rules.md`.
5. **Цветокор.** Варианты грейда к готовому превью (до подписи). Ждать выбор
   пользователя перед любым «финалом». Правила — `references/color.md`.
6. **Выдача.** EDL/OTIO + превью грейда + **критический разбор с таймкодами
   брака** + **shot list на следующий полёт** (чего не хватило). Разбор — честный.

- `references/color.md` — двухэтапный грейд, что можно/нельзя выравнивать,

- `references/batches.md` — реестр партий, их специфика и готовые команды.
