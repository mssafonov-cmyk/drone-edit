# Доктрина отбора кадров и валидации ДО рендера

Скоринг этапа 2 сам по себе даёт «грязный» монтаж: любит цветастый дневной кадр,
недооценивает плавность и вечерний свет, не знает о смысле. Поэтому финальный
отбор — ручная курация по правилам ниже. Рендер длинного ~5 минут, перебор
итераций дорог: **валидируй список планов метриками ДО рендера**, а не после.

## ШАГ 0 — ВАУ-СКАН: обязателен на КАЖДОЙ партии, до любого отбора
Метрики видят ТЕХНИКУ (дрожь/рывки/резкость), но не КРАСОТУ — отбор только по
чистым окнам теряет жемчужины (проверено на Сейшелах: контровой катамаран на
закатной дорожке, портрет лодки анфас, графичные топ-дауны мола/рифа метрики
либо резали, либо не выделяли из «просто чистых»).

Процедура:
1. Контактный лист ВСЕХ клипов партии: по 5 кадров с клипа (10/30/50/70/90%
   длительности), листы по ~19 клипов (ffmpeg xstack), отсмотреть ГЛАЗАМИ.
2. Собрать **вау-пул с ранжированием**: каждому кандидату — пометка «вау» /
   «сильный» / «фон». Вау-кадры проверить метриками (для контровых — режим
   `forced=True`: недосвет силуэта — ложный брак).
3. Монтаж строить ОТ вау-пула: вау — в хук, кульминацию и финал; «сильные» —
   в опорные точки глав; «фон» — только связки. Лучшее берётся в работу всегда,
   даже если чистых «фоновых» окон больше.
4. Вау-кадры, неспасаемые технически (короткие/рваные), — в shot list следующего
   полёта с пометкой «переснять длинным плавным дублем».

## Главное правило (прямая цитата пользователя)
**«Если материала нет — лучше отказывай в склейке или предлагай короткий ролик».**
НЕ растягивать плохой материал, НЕ добивать браком поворотные/статичные планы.
Честно: «на полноценный рилс/фильм чистого материала не хватает, предлагаю
короткий на N секунд» — лучше, чем отдать посредственное. «Лучше подрежь, чем
бери плохой кадр».

## Валидатор: прогнать КАЖДЫЙ кандидат ПЕРЕД сборкой
Из посекундных метрик `clip_catalog.json` (`flow`, `jerk`, `curl`, `ang`).
Отбрасывать сегмент/окно, если:
- `jerk.max() > 0.6` (в фильмах строже) → рывок скорости.
- `flow.mean() < 1.2` → почти статичный (камера стоит).
- `flow.max()/flow.min() > 3` → старт-стоп («стоит, потом летит»).
- `curl > 0.9` → вращение/орбита/крен (см. контекст ниже).
- дрейф угла `ang` по окну `> 55–60°` → доворот (yaw), «болтается».
- **статичный ВХОД**: первый кадр окна `flow < 0.5` → почти дисквалификация
  (штраф 1.5); первые 2с `< 0.7` → штраф. Особенно критично для `--open-with`.
- **статичный ВЫХОД / спайк на выходе**: последняя секунда — резкий всплеск
  (`tail > body*2.2`) → план «подлетает» в конце, срезать.
- **разгон-с-места**: `flow` первой секунды `< 0.6`, дальше заметно быстрее →
  резать там, где движение УЖЕ идёт, а не из стоп-кадра.

Собирать `--prefer` только из прошедших, с ЗАПАСОМ (иначе хвост автозаполнится
случайными грязными сегментами — `rest_pool` = prefer + все остальные по скору,
break нет). Для длинного `--prefer` ДОЛЖЕН покрывать ВСЕ ~45 слотов в точном
порядке — автозаполнению места не оставлять.

Окно внутри сегмента выбирает САМ скрипт (`best_window_of_length`,
`smooth_weight`), поэтому правило плавности живёт в коде — ручным списком не
заменить. `--prefer` называет СЕГМЕНТ; `--window` форсирует старт окна (нужно,
когда сегмент короткий и окну негде уехать от плохого входа).

## Контровой свет / солнце в кадре = ДОРОГИЕ кадры, не брак
Пользователь особо просил это помнить. Разворот камеры на солнце, контровой
силуэт, закатная дымка — **самые ценные, «дорогие» кадры**. Детектор брака
этапа 2 метит их как недосвет (силуэт тёмный против солнца) — это ЛОЖНОЕ
срабатывание. Брать вручную через `--window` (обходит границы сегмента и
детектор). Эталон: `DJI_0070` 10.5–18.5с (Ниньбинь, разворот пагоды на солнце) —
поставлен финалом-кульминацией. Искать такие моменты ЦЕЛЕНАПРАВЛЕННО.

## Поворот/облёт — КОНТЕКСТ решает
- В быстром reveal-монтаже (рилсы, средние планы) микродовороты «болтаются» —
  убирать (curl высокий + короткий план = болтанка).
- Осознанный медленный ОБЛЁТ объекта-героя в финале/showcase — это ПРИЁМ, он
  хорош (облёт бунгало, круглой террасы Đồi Mâm Xôi). Curl умеренный + длинный
  финальный план на герое = кинокадр.
- Салют/фейерверк, где камера ВИСИТ — субъект сам движется, штрафы за
  статику/поворот неуместны (как облёт объекта).

## Нарративная курация обязательна — автоподбор по скору её НЕ даёт
Скор не знает смысла. Рилс с ручной драматургией («хук-водопад → туман → долины →
водопады кульминацией») пользователь оценил «безупречно»; автоподбор по скору —
«кадры вперемешку, то дорога, то ещё что-то». ВСЕГДА выстраивать порядок вручную
через `--prefer` + `--end-with`, финал — самый «дорогой» кадр.
- **Длинный ролик (16:9 или вертикальный), правка 2026-08-31:** ВАУ-ХУК В НАЧАЛО
  и у фильмов тоже (пользователь: «вау-эффект в начало — эти части используй
  дальше»; IG-зритель не ждёт раскачки). Драматургия: вау-хук → спокойное
  развитие → нарастание → кульминация → закатная кода с длинным затуханием.
  Прежнее «спокойное начало» отменено. Отражать структуру трека: тихая часть →
  общие планы, ритм → динамика.
- **Музыка фильма — мягкий вход:** без удара в первую секунду («резкий вход —
  для длинного так не делать»): фрагмент выбирать с тихого нарастания, не с
  пика, + `--in-fade 2.0` в сборке; финал — `--end-fade 2.5`.
- **Рилс (9:16):** самый эффектный кадр ПЕРВЫМ (хук в первые 1–2с, иначе
  пролистают). Длина — целиться в ~60с, если материала хватает (алгоритм смотрит
  % досмотра; 60–90с обходят короткие по вовлечённости для travel/cinematic),
  снап на границу муз. фразы. Петля Reels/TikTok: финал должен рифмоваться с
  хуком (`--end-with`).

## Правила, зашитые в код гейта (doctrine.py / validate_shots.py)
Эти проверки исполняет код — но помнить их надо и при ручном отборе:
- **yaw_spot (hard):** разворот на месте — посекундно `turn>6` И `turn/flow>12`
  (развороты 21–242, чистые пролёты и пан-в-полёте ≤5.4). Окно проверки
  расширяется до последней ЧАСТИЧНОЙ секунды рендера (пики в хвосте ускользали).
  Партии, одобренные до правила, и партии, где облёты — фича, освобождаются
  флагом `orbits_ok: true` в `curation_<batch>.json` (облёт от разворота метрики
  не отличают — различие в удержании объекта).
- **dead_start (hard, любой слот):** первая секунда `flow<0.15` при максимуме
  окна `>0.6` — «кадр стоит и только потом едет». Лечится сдвигом окна.
- **Контент-чек рендера (hard):** кадр из середины каждого слота коррелируется
  с кадром исходника; кадр за пределами рендера = hard (ловит обрезку/подмену).
  Длину сверять по ВИДЕОПОТОКУ (`stream=duration`) — контейнер врёт (аудио длиннее).
- **Мульти-окна и в фильмах:** клип можно использовать повторно, если сменился
  свет/план; зазор ≥8с, в таймлайне не соседями. Энергичный трек = чаще смена
  (фильм ~4.2с/план, не 5.7).
- **Палитра при разбавке:** в тематический блок — только кадры той же световой
  палитры, что якорные (в тёплый рассвет дневной сине-белый снег «сильно
  выбивается»). Нет тонального совпадения — лучше укоротить.
- **Метка «трек @ секунда»** в имени файла и подписи — с ЗАМЕРА аудио финального
  рендера (кросс-корреляция), не из планировщика (он недетерминирован); для
  зацикленных треков — start_time из shots.json.

## Мелкие, но заметные правила
- **Джамп-кат:** не ставить два окна ОДНОГО клипа подряд (дедуп по сигнатуре их
  пропускает — чуть разные, — но рядом читаются как «дёргается картинка»).
- **Из одного длинного дубля — несколько частей**, разнесённых >6с, максимум ~2с
  каждая, чтобы не читалось повтором.
- **Минимальная длина плана 2.5с** — кадр должен «прожиться». Короче — только
  осознанный акцент.
- Границы глав/локаций (`candidate_idx`) заданы с умом (напр. idx47 сознательно
  НЕ Халонг — это уже следующая глава). Не двигать без визуальной проверки кадра,
  даже если кажется багом.

## Ориентация партии инвертирует правило кропа
Правило 9 (кроп 16:9→9:16 с трекингом) применимо, только если материал
горизонтальный. У вертикально-снятых партий (Вьетнам: 88 верт / 19 гориз) рилсы
и даже длинный ролик берут из НАТИВНОЙ вертикали без кропа, а горизонтали мало.
Всегда проверять фактическое соотношение сторон партии и решать «делаем из того,
чего больше». Трекинг-кроп (`vertical_crop.py`) — когда нужно втянуть
горизонтальный материал в вертикаль: карта интересности (контраст Sobel +
отклонение от фона) → X-центр, EMA-сглаживание (`config → vertical_crop.smoothing`).
Кроп в OTIO/EDL для Resolve НЕ переносится метаданными — только для превью,
ретайм/кроп в Resolve вручную (`_track.csv` в помощь).
